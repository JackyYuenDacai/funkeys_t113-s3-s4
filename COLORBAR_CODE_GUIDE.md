# Colorbar Command Code Location Guide

## Overview
The `colorbar` command in U-Boot sunxi disp2 driver generates test patterns for display debugging.

## Expected File Locations

### 1. U-Boot Command Definition
The colorbar command is typically defined in one of these locations:

**Primary Location:**
```
drivers/video/sunxi/disp2/disp/cmd/disp_cmd.c
```
or
```
drivers/video/sunxi/disp2/cmd/disp_cmd.c
```

**Alternative Locations:**
- `cmd/sunxi_disp.c`
- `drivers/video/sunxi/disp2/disp/de/disp_cmd.c`
- `drivers/video/sunxi/disp2/disp/dev_disp.c`

### 2. Command Handler Function
The command handler function is likely named:
- `do_colorbar()` or `cmd_colorbar()`
- Registered with `U_BOOT_CMD()` macro

### 3. Implementation Functions

**For colorbar 0 (framebuffer picture):**
- Uses framebuffer data
- Location: `drivers/video/sunxi/disp2/disp/dev_fb.c` or similar

**For colorbar 1-7 (TCON built-in patterns):**
- Hardware TCON test patterns
- Location: `drivers/video/sunxi/disp2/disp/de/lowlevel_*/tcon*.c`
- Function: `tcon_set_colorbar()` or `tcon_colorbar_enable()`

**For colorbar 8 (DE colorbar):**
- Display Engine generated pattern
- Location: `drivers/video/sunxi/disp2/disp/de/lowlevel_*/de*.c`
- Function: `de_set_colorbar()` or `disp_al_set_colorbar()`

## How to Find the Code

### Step 1: Search in U-Boot Source
```bash
# In your U-Boot source directory (usually in buildroot/dl/uboot-* or SDK)
cd <uboot_source>
find . -name "*.c" -type f | xargs grep -l "colorbar"
```

### Step 2: Search for Command Registration
```bash
grep -r "U_BOOT_CMD.*colorbar" .
grep -r "colorbar.*show colorbar" .
```

### Step 3: Search for Implementation
```bash
grep -r "tcon.*colorbar\|de.*colorbar\|disp.*colorbar" .
```

### Step 4: Check TCON Registers
```bash
# TCON colorbar is typically controlled by registers
grep -r "TCON.*COLORBAR\|TCON.*PATTERN" .
```

## Key Functions to Look For

### Command Handler
```c
static int do_colorbar(cmd_tbl_t *cmdtp, int flag, int argc, char * const argv[])
{
    // Parse arguments: colorbar <mode> [screen]
    // mode: 0-8
    // screen: 0-3 (optional)
}
```

### TCON Colorbar (modes 1-7)
```c
// In tcon*.c or lowlevel_*.c
void tcon_set_colorbar(u32 sel, u32 mode)
{
    // Write to TCON registers to enable built-in patterns
    // TCON_TCON0_IO_POL_REG or similar
}
```

### DE Colorbar (mode 8)
```c
// In de*.c or disp_al.c
s32 disp_al_set_colorbar(u32 screen_id, u32 mode)
{
    // Configure DE layers to generate colorbar pattern
    // Uses DE layer composition
}
```

### Framebuffer Colorbar (mode 0)
```c
// In dev_fb.c
void fb_fill_colorbar(struct fb_info *info)
{
    // Fill framebuffer with colorbar pattern
    // Uses software rendering
}
```

## Register Locations

### TCON Colorbar Registers (for modes 1-7)
- Base: `TCON_BASE` (typically `0x06000000` for TCON0)
- Register: `TCON_TCON0_IO_POL_REG` or `TCON_TCON0_CTL_REG`
- Bit fields for pattern selection

### DE Colorbar (for mode 8)
- Uses DE layer registers
- Base: `DE_BASE` (typically `0x01000000`)
- Layer configuration registers

## Typical Code Flow

```
colorbar command
    ↓
do_colorbar()
    ↓
    if (mode == 0)
        → fb_fill_colorbar()  // Software framebuffer
    else if (mode == 8)
        → disp_al_set_colorbar()  // DE hardware
    else (mode 1-7)
        → tcon_set_colorbar()  // TCON hardware
```

## Why Colorbar 8 Works But 1-7 Don't

**Colorbar 8 (DE colorbar):**
- Generated by Display Engine
- Passes through TCON with proper layer configuration
- Respects DE layer `crop` and `frame` settings
- Uses correct coordinate system

**Colorbar 1-7 (TCON patterns):**
- Generated directly by TCON hardware
- Bypasses DE layer settings
- Uses TCON's internal coordinate system
- May not respect panel timing offsets
- This is why they show displacement

## Debugging Tips

1. **Check TCON register values:**
   ```c
   // In U-Boot, you can read TCON registers
   md.l 0x06000000 0x100  // Read TCON registers
   ```

2. **Check DE layer configuration:**
   ```c
   // DE layer registers
   md.l 0x01000000 0x100  // Read DE registers
   ```

3. **Enable debug output:**
   - Look for `DE_WRN`, `DE_INF`, or `printf` statements
   - Check if colorbar mode is being set correctly
